1.3 SECTION 2: COT SIGNAL VERIFICATION (MONTE CARLO)

This is the most important section. It answers the question: “Are our COT signal grades genuinely predictive, or could they have occurred by random chance?”

Data source: Use the existing COT backtest data that is already available in the application. If the backtest has been run, pull the signal history. If not, display a message: “Run a COT Backtest first to enable signal verification.”

Monte Carlo Simulation Engine (implement in pure TypeScript):

For each signal grade (A, B+, B) and each instrument (XAUUSD, EURUSD, GBPUSD):

  Step 1: Get the actual signal returns (4W returns for all signals of this grade/instrument)
  Step 2: Calculate actual win rate, mean return, Sharpe ratio
  Step 3: Run 10,000 Monte Carlo simulations:
    - For each simulation, randomly select N dates from the instrument’s price history
      (where N = number of actual signals)
    - Calculate the 4-week forward return for each random date
    - Calculate the win rate, mean return, and Sharpe for this random simulation
  Step 4: Build the distribution of 10,000 random Sharpe ratios
  Step 5: Calculate what percentile the actual Sharpe falls in
  Step 6: Calculate the p-value: proportion of random simulations that
      produced a Sharpe equal to or better than the actual

Display for each grade/instrument combination:
  - Actual win rate vs random mean win rate (with difference highlighted)
  - Actual Sharpe vs 95th percentile of random Sharpe distribution
  - p-value with significance stars (*** p<0.01, ** p<0.05, * p<0.1)
  - A histogram chart (Recharts BarChart) showing the distribution of 10,000 random
    Sharpe ratios, with a vertical line marking the actual Sharpe
  - Verdict: “GENUINE ALPHA” if p < 0.05, “MARGINAL” if p < 0.10,
    “NOT SIGNIFICANT” if p >= 0.10

MCMC Bayesian Inference (implement Metropolis-Hastings in TypeScript):

For each signal grade on XAUUSD (the instrument with the edge):

  Prior distribution: Beta distribution with alpha=2, beta=2 (uninformative prior
    centered at 50% win rate) — OR use the Dreesmann paper’s reported win rate
    as an informed prior (Beta distribution centered at the Dreesmann value)

  Likelihood: Binomial (wins out of N signals)

  Metropolis-Hastings sampler:
    - Parameter to estimate: true underlying win rate (theta, bounded 0 to 1)
    - Proposal distribution: Normal(theta_current, 0.02), reflected at 0 and 1
    - Run 50,000 iterations (discard first 10,000 as burn-in)
    - Store the posterior samples

  Calculate and display:
    - Posterior mean win rate (point estimate)
    - 95% credible interval (2.5th and 97.5th percentiles of posterior)
    - Posterior standard deviation
    - A density chart (Recharts AreaChart) showing the posterior distribution
      with the 95% CI shaded and the prior distribution overlaid as a dashed line
    - Interpretation text: “Given the data and prior, there is a 95% probability
      the true win rate is between X% and Y%”

Also run MCMC on the MEAN RETURN (not just win rate):
  - Prior: Normal(0, 2%) — we believe the true mean return is near zero
  - Likelihood: Normal(actual_returns, observed_std)
  - Estimate the posterior distribution of the true mean return
  - Display: posterior mean, 95% CI, and density chart
  - This answers: “What is the true expected return per signal?”

1.4 SECTION 3: BACKTEST RESULT VERIFICATION

This section verifies the integrity and robustness of the backtest results.

Bootstrap Sharpe Ratio Confidence Interval:
  For the overall backtest strategy (all signals on XAUUSD LONG):
    - Take the actual 4W returns array
    - Resample with replacement 10,000 times (each resample = same size as original)
    - Calculate Sharpe for each bootstrap sample
    - Report: Actual Sharpe, Bootstrap 95% CI [lower, upper], Bootstrap mean
    - Display as a chart: histogram of bootstrap Sharpe distribution with CI marked

Overfitting Detection:
  - Calculate the ratio: Out-of-Sample Sharpe / In-Sample Sharpe
  - If ratio >= 0.70: “NO SIGNIFICANT OVERFITTING” (green)
  - If ratio 0.50-0.69: “MODERATE OVERFITTING RISK” (amber)
  - If ratio < 0.50: “SEVERE OVERFITTING DETECTED” (red)
  - Display a comparison bar: In-Sample Sharpe vs Out-of-Sample Sharpe

Walk-Forward Validation Score:
  - Divide the data into 6 rolling windows (each ~4 years)
  - Calculate Sharpe for each window
  - Calculate the coefficient of variation (std/mean) across windows
  - Lower CV = more consistent performance = more robust
  - Display: line chart of rolling Sharpe over time
  - Flag any window where Sharpe < 0 as a “failure period”

Multiple Testing Correction:
  - Count total hypothesis tests: grades (3) x instruments (3) x horizons (5) = 45 tests
  - Apply Bonferroni correction: significance threshold = 0.05 / 45 = 0.00111
  - Apply Benjamini-Hochberg FDR correction
  - For each significant result, report: uncorrected p-value, Bonferroni-corrected
    significance, BH-adjusted q-value
  - Display a table showing which results survive correction
  - This is critical — it shows whether the edge is real after accounting for
    the fact that we tested many combinations
